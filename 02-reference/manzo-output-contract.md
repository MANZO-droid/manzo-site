# 만조리서치 Top10 종목 분석 — 출력 규격 (코드 기준, 2026-07-25 확인)

`scripts/collect_gainers.py`의 `analyze_stock()`이 실제로 요구·생성하는 값을 그대로 옮긴 기준입니다.
"정답"이 아니라 검토 기준이며, 코드가 바뀌면 이 문서도 다시 확인해야 합니다.

## Gemini에게 실제로 전달되는 입력

- 종목명, 종목코드, 날짜, 당일/주간 상승률(%)
- 수집된 뉴스 기사(최대 15개, `title`+`summary`), 없으면 "수집된 기사 없음"으로 대체하고 추정 작성 지시
- **전달되지 않는 것**: `technicals`(ma5/ma20/ma60/ma120/volRatio/trend/cross 등), `ohlcv`, `financials` — 이 값들은 같은 JSON 항목에 같이 저장되지만 Gemini 프롬프트 문자열에는 들어가지 않음

## 출력 필드와 최소 분량

| 필드 | 최소 분량 | 근거 |
| --- | --- | --- |
| `riseReason` | 200자 이상 | 프롬프트 지시 "반드시 200자 이상 작성" |
| `chartAnalysis` | 600자 이상 | 프롬프트 지시 "반드시 600자 이상 작성" (이동평균선 배열·거래량 특이점·지지저항·추세·향후 가격대·리스크 요인 포함 지시) |

뉴스가 있으면: "기사에서 확인된 핵심 급등 원인만, 추측 금지, 구체적 수치는 반드시 포함."
뉴스가 없으면: "추정임을 명시하되 구체적으로 작성" (추측 허용 — 뉴스 있을 때와 기준이 다름).

## 사람 검토 체크리스트

- **사실관계**: `riseReason`에 적힌 근거(계약·수주·이슈 등)가 실제로 수집된 기사 제목/요약에 있는가? 기사에 없는 사실이 섞여 있지 않은가?
- **수치 일치**: `chartAnalysis`가 묘사하는 이동평균 배열·골든/데드크로스·거래량 상태가 같은 항목의 `technicals` 실제 값과 맞는가? (Gemini는 이 숫자를 보지 못하고 쓰므로 어긋날 수 있음 — 반드시 대조 필요)
- **분량**: `riseReason` 200자 이상, `chartAnalysis` 600자 이상인가?
- **필터링**: 우선주·관리종목·ETF·정리매매 종목이 Top10에 섞여 있지 않은가? (현재 코드에 자동 필터링이 없어 사람이 직접 확인해야 함)
- **빈 값**: `news`가 비어 있는데 `riseReason`이 추정 없이 단정적으로 쓰이지 않았는가? `financials`가 `{}`인데 화면에 재무 수치인 것처럼 보이지 않는가?

## 게시(배포)

`git_push()`가 스크립트 실행 안에서 조건 없이 자동 실행됨 — 사람이 막을 지점이 코드에 없으므로, 위 체크리스트는 **게시 이후 사후 검토**로만 적용 가능. 문제 발견 시 수정 후 재실행/재커밋이 필요.
