# 회원 일일 메일 (조건 검색 결과 + 보유 종목 알람) — 2단계 설계서

작성: 2026-11-02 · 상태: **설계안 (구현 전, 회장님 승인 대기)**
선행: 1단계 `2026-11-02-member-mail-consent-design.md` (수신 동의·비열람 안내, 병합·배포 완료)
관련: `2026-10-25-member-report-addendum.md` (요청형 종목 리포트, 이 문서의 "보유 종목 알람" 부분이 재사용)

## 1. 정해진 것 (회장님 결정)

- **방식**: PC는 자료만 올리고, GitHub가 발송한다.
- **내용**: 회장님이 받는 일일 리포트(스터디 종목)와 **정보는 같다.** 다만 종목의 매수·매도를 권하는 것으로 오해할 만한 **단어만 바꾼다.**
- **받는 사람**: 마이페이지에서 메일 수신에 동의한 회원만.
- **주기**: 거래일 장 마감 후 하루 1통.
- **보유 종목 알람**: 회원이 등록한 종목이 있으면 그 종목의 알람 리포트를 같은 메일에 담는다(이수페타시스 메일과 같은 형식).
- **제외**: 회장님 본인의 "보유 종목 신호"(매수가·수익률·청산 사유)는 어떤 형태로도 올리지 않는다.

## 2. 전체 흐름

```
[회장님 PC, 매일 run_daily.ps1 끝]
  stock_screener가 일일 리포트 자료를 만든다
  → publish_daily_picks.py 가 "스터디 종목 사실 자료"만 Supabase member_daily_picks 에 올린다
        (회장님 보유·매수가·수익률은 읽지도 올리지도 않음)

[GitHub Actions, 21:00 KST 거래일, PC 게시 이후]
  member_daily_mail.py
   1) 오늘 자료가 올라왔는지 확인(없으면 발송하지 않고 회장님께 알림)
   2) 동의 회원 목록(member_mail_consent.digest_consent = true) 조회
   3) 회원별 메일 조립: [조건 검색 결과 N종목] + [내 보유 종목 알람(있으면)]
   4) 금지 표현 검사 → 통과한 메일만 Gmail 발송기로 발송
   5) 회원·날짜별 발송 기록(member_daily_mail_log)으로 하루 1통 보장
```

이유: 단어를 바꾸는 규칙과 검사기가 **한 곳(GitHub 저장소)** 에만 있어야 PC 쪽을 건드리지 않고 문구를 고칠 수 있고, 기존에 검증한 Gmail 발송기·승인 변수·금지 표현 검사를 그대로 재사용한다.

## 3. 올리는 자료 (PC → DB): `member_daily_picks`

PC가 올리는 것은 **완성된 문장이 아니라 사실 값**이다(문장은 GitHub가 만든다).

| 열 | 내용 |
|---|---|
| pick_date, rank (PK) | 기준 거래일, 순위 |
| stock_code, stock_name, price | 종목, 종가 |
| score | 회장님 리포트의 추세점수 값 |
| align_days | 5·20·60일선 정배열 지속 거래일 |
| new_high (bool), days_since_high | 오늘 60일 신고가 여부 / 마지막 60일 신고가 후 경과일 |
| disp_pct | 20일선 대비 위치(%) |
| rsi, atr_pct | RSI, 일간 변동폭(%) |
| drop_price, drop_price_atr | 현재가 -3% 가격 / 변동폭 기준 가격 (§5-2 결정 사항) |
| news (jsonb) | `[{title, link}]`, 시황 기사로 분류된 것은 제외된 목록 |
| news_negative_count | 악재로 분류된 기사 수 |
| chart_png (text, base64) | 일봉 차트 이미지(종목당 수십 KB) |

- RLS 켜고 정책 없음, 회원·비로그인 접근 차단. 서버(service role)만 읽고 쓴다.
- PC 쪽 `daily_report.py` 의 `chart_story` 는 **그대로 둔다**(회장님 본인 리포트 문장 불변). 사실 값은 `chart_facts(g)` 라는 별도 함수로 같은 계산을 한 번 더 한다. 두 함수의 값이 어긋나지 않는지 **일치 테스트**를 둔다(전에 JS↔Python 일치를 401개 입력으로 검증한 방식).

## 4. 발송 기록 표 (`member_daily_mail_log`)

| 열 | 내용 |
|---|---|
| user_id, send_date (PK) | 회원, 발송일(KST) |
| status | `sent` / `error` / `skipped` |
| holdings_count | 담은 보유 종목 수(개수만, 종목코드 저장 안 함) |
| sent_at, error_message(마스킹) | |

- 같은 회원·같은 날 두 번째 실행은 이미 `sent` 이면 건너뛴다(하루 1통 보장, 재실행해도 중복 없음).
- 이 표에는 **종목코드·이메일을 넣지 않는다**(회장님이 회원 보유를 보지 않는 원칙).

## 5. 내용과 문구

### 5-1. 메일 구성

제목: `[만조] 2026-11-03 오늘의 차트 조건 검색 결과 5종목`
1. **조건 검색 결과 N종목** (회장님 메일의 "스터디 종목" 카드와 같은 항목: 종목·종가·차트 이미지·차트상 위치·재료 기사 링크)
2. **내 보유 종목 알람** (동의 회원 중 리포트 허용 + 등록 종목이 있을 때만, 종목당 한 칸, 최대 10종목 + "외 N종목")
3. 하단: 면책 문구, 수신거부 방법(My page에서 체크 해제), 계산 기준 안내

### 5-2. 오해 소지가 있는 표현 → 바꿀 표현

원칙: **"왜 사야 하는지"가 아니라 "차트에서 어떤 조건이 충족됐는지"만 사실로 적는다.** 값(숫자)은 그대로 두고 판단을 암시하는 말만 바꾼다.

| 구분 | 현재 표현(회장님용) | 회원용 표현 |
|---|---|---|
| 메일 제목·머리말 | 추세추종 일일 리포트 / 스터디 N종목 | 오늘의 차트 조건 검색 결과 N종목 |
| 섹션명 | 추천 종목 | 조건 충족 종목 |
| 카드 강조문장 | 오래 다져온 상승 추세가 신고가로 이어지는 자리 | 정배열이 20거래일 이상 이어지고 있으며 오늘 60일 신고가를 기록했습니다 |
| | 한 달 넘게 흐트러지지 않은 꾸준한 상승 추세 | 정배열이 20거래일 이상 이어지고 있습니다 |
| | 신고가를 새로 쓰며 추세가 막 자리를 잡는 구간 | 오늘 60일 신고가를 기록했습니다 |
| | 20일선을 내주며 추세가 꺾인 자리 | 20일선 아래에서 거래되고 있습니다 |
| | 상승 추세가 살아 있으나 아직 다져지는 중 | 정배열 상태이며 지속 기간은 짧은 편입니다 |
| 차트상 위치 | 20일선 −x% 아래 (추세 이탈) | 20일선 −x% 아래에 있습니다 |
| | RSI n (과열 구간 / 상승 탄력 구간 / 탄력 약화) | RSI n (75 초과 / 50~75 / 50 미만) |
| | 일간 변동폭 n% (잔잔한 편 / 흔들림이 큼) | 일간 변동폭 n% (3% 미만 / 3~5% / 5% 이상) |
| 점수 | 추세점수 0.xxx | 차트 조건 점수 0.xxx |
| 가격 | 하락 참고선 ○○원 (변동성 기준 참고선) | 현재가 −3% 가격 ○○원 (**§7 결정 사항**) |
| 경고 문장 | 별일 없이도 하락 참고선에 닿을 수 있으니… | 일간 변동폭이 n%로 큰 편입니다. 최근 공시·실적에 변화가 있었는지 확인해 보시기 바랍니다 |
| | 단기간에 크게 오른 뒤라 되돌림이 나오면… | 20일선보다 n% 높은 위치입니다(단기간 상승폭이 큰 상태) |
| 기사 요약 | 재료 판단은 보류합니다 | 관련 기사가 없습니다 |
| | 악재로 분류된 건이 n건… 직접 확인하십시오 | 기사 n건 중 부정적 표현이 포함된 기사가 m건 있습니다 |
| 하단 설명 | …가장 오래 붙잡고 있을 수 있는 종목을 찾는 방식입니다 | 순위는 정배열 지속일수와 변동성 대비 상승 속도 등을 점수로 계산한 순서이며, 이 점수가 종목의 향후 흐름을 뜻하지 않습니다 |
| 마무리 | 최종 매수·매도 판단은 직접 하십시오 | 이 메일은 공개된 시세·뉴스를 조건에 따라 정리한 정보이며 특정 종목의 매수·매도를 권유하지 않습니다. 투자 판단과 책임은 본인에게 있습니다 |

### 5-3. 자동 검사 (발송 직전, 통과 못 하면 그 회원 메일은 발송하지 않고 회장님께 알림)
- 조립된 본문(고정 면책 문구 제외)에 **금지 표현**이 있으면 중단: 매수, 매도(단, 순매수·순매도는 허용), 추천, 후보, 손절, 목표가, 전망, 예상, 기대, 진입, 청산, 처분, 눌림, 저점, 급등 예상, "~할 것", "~가능성" 등. 목록은 기존 회원 리포트 검사기(`member_report.py`)와 **같은 규칙을 공유**하고 위 항목을 보강한다.
- 선정 이유를 설명하는 문장형 서술 없이, 정해진 문장 틀(표 §5-2)에 값만 채운다(AI가 자유롭게 쓰는 문장은 이 메일에 넣지 않는다. 보유 종목 알람의 AI 설명 문단은 기존처럼 검사를 통과한 것만 사용).

## 6. 안전장치(발송 관문)

1. 기존 `MEMBER_REPORT_SEND_APPROVED = yes` 변수와 Gmail 비밀값이 있어야만 발송.
2. **단계 제한**: 새 변수 `MEMBER_DAILY_TEST_ONLY`(허용 주소 목록)가 설정되어 있는 동안에는 **동의한 회원이라도 그 목록의 주소로만** 발송한다. 회장님이 검토하고 `MEMBER_DAILY_RELEASE_ALL = yes` 를 직접 등록하기 전까지 다른 회원에게는 나가지 않는다.
3. 수동 실행(`workflow_dispatch`)부터 시작한다. 자동 실행(21:00 스케줄)은 시험 발송이 끝난 뒤에 연결한다.
4. 자료가 오늘 날짜가 아니거나 비어 있으면(휴장일·PC 꺼짐) 발송하지 않고 회장님께 한 줄 알림.
5. 한 번 실행에 보낼 수 있는 최대 건수 제한(Gmail 하루 500통 한도 보호)과 건당 간격.
6. 로그에는 개수만 남긴다(회원 이메일·종목코드 금지).

## 7. 회장님 결정이 필요한 것

1. **"현재가 −3% 가격"을 회원용 메일에 넣을지.** 정보를 같게 하신다는 방침에 따라 넣는 안으로 설계했지만, 오늘 종가의 −3% 가격은 회원이 **손절 가격으로 받아들일 가능성이 가장 큰 항목**입니다. **제 권고는 회원용에서는 뺀다**입니다(회장님 본인용 메일에는 그대로). 넣으시면 이름은 "현재가 −3% 가격"으로 하고 설명 문장을 붙입니다.
2. 차트 이미지를 메일에 포함할지(권장: 포함, 종목당 수십 KB).
3. 발송 시각(권장: 거래일 21:00 KST, PC 게시가 끝난 뒤).
4. **일반 회원 공개 전 전문가 확인**: 불특정 회원에게 종목별 조건 충족 목록을 정기적으로 보내는 일이 투자자문 규제에 해당하는지, 광고성 정보 표시 방식(제목 표기, 야간 발송 제한)이 필요한지. 저는 법률 판단을 확정할 수 없으므로 첫 시험은 회장님 계정으로만 하고, 확인 후에 `MEMBER_DAILY_RELEASE_ALL` 을 켭니다.

## 9. 위험과 대응

| 위험 | 대응 |
|---|---|
| 순위·조건 충족 목록이 매수 추천으로 읽힘 | 문장 틀 고정, 판단 암시어 제거, 금지 표현 자동 검사, 면책 문구, 공개 전 전문가 확인 |
| 동의하지 않은 회원에게 발송 | 동의 표에서 `digest_consent = true` 만 조회, 테스트로 보장, 단계 제한 변수 |
| 같은 회원에게 하루 두 번 발송 | `member_daily_mail_log` 기본키 + 이미 `sent` 이면 건너뜀 |
| 회장님 개인 보유·신호 노출 | PC 게시 스크립트가 추천 종목(`buys`)만 읽고 `sells`·원장은 읽지 않음, 테스트로 확인 |
| 자료가 어제 것이거나 비어 있음 | 오늘 날짜 확인, 없으면 발송 중단 + 알림 |
| PC가 꺼져 있어 게시가 안 됨 | 위와 같음. 다음 거래일에 정상 발송 |
| Gmail 한도·스팸 분류 | 건수 제한, 공개 전 도메인 발송 서비스 재검토(기존 문서 §5) |
